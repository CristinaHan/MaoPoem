# 毛诗知识库

用户打开 App 时，程序**不再读这三本书**。它只显示已经写好的诗条。三本 EPUB 是编辑用的原料。

```text
鉴赏目录（哪几首诗） + 年谱/传记（同一时期）
        ↓ 人写成连贯的背景和解读
content/poems/*.json
        ↓ python tools/kb.py
web/data/poems.js          ← 只有这一份进用户包
```

不要把「分析过程」做进用户 App，也不要用模型对着书现搜现编。缺材料就写「这篇尚未写就」。

## 目录

| 路径 | 作用 |
|---|---|
| `catalog.json` | 鉴赏正编、副编里带【考辨】的诗，共 63 首。这是编辑队列。 |
| `poems/*.json` | 已经写成、可以进 App 的诗条。 |
| `poems/_template.json` | 新诗字段样板，编完后不要用这个文件名。 |
| `../tools/kb.py` | 从鉴赏 `toc.ncx` 刷新目录；把 `poems/` 编进 `web/data/poems.js`。 |

附录里的书信、解释不是诗，不进队列。

## 写一首诗

1. 在 `catalog.json` 里找这首，记下 `id` 和鉴赏 `src`。
2. 鉴赏：题下的时间地点、【考辨】、注释、赏析。
3. 年谱：同一年、同一月，人在哪里、在做什么。
4. 传记：同一时期的叙述，用来把事实写成段，不拿来发明心理。
5. 复制 `_template.json` 为 `poems/<id>.json`，`order` 接在现有数字后面。
6. 跑 `python tools/kb.py`。目录会把这首标成 `published`。

材料对不上的字段留空，详情页会显示「这篇尚未写就」。不要用网上的赏析补洞。

## 正文怎么写

- 以评论者的口吻写，不要「年谱说 / 传记记载 / 鉴赏写道」。
- 写完整的白话。人名用「毛泽东」，不要一路「他」。
- 背景是合成叙述，不是把三条材料并排放。
- 日期用阿拉伯数字。
- 不做「启示我们」、职场应用、无出处的心理分析。
- 后见之明如果必须写，标在解读末段，不要混进写作当时。

## 诗句怎么写（首页拆句规范）

- `lines` 每行一句（一联），**句号结尾，必须完整**——首页随机展示时按行（句号单位）抽取，每个句子都有机会上首页。
- 律诗 8 个单句 → 4 行（每行一联）；绝句 4 个单句 → 2 行（每行一联）。例：「正是神都有事时，又来南国踏芳枝。」是 1 行。
- 不要只给半句（如单独「满街红绿走旌旗」）——那是用户回忆不起上句时的示例，正式库必须给完整联。
- `excerpt` 是可选的「代表句」，用于搜索/收藏列表展示；留空时程序自动取 `lines[0]` 兜底。

## 命令

在仓库根目录：

```text
python tools/kb.py           刷新目录 + 重编 poems.js
python tools/kb.py catalog   只刷新目录
python tools/kb.py poems     只重编 poems.js
python tools/kb.py dump      从现有 poems.js 拆回 json（会覆盖 poems/）
```
