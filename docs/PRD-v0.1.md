# 毛诗 · 产品需求文档（PRD）v0.1

| 项 | 内容 |
|---|---|
| 产品暂名 | 待定（姐妹定位：毛诗版，对标「问问毛选」的文章金句版） |
| 文档状态 | 讨论冻结后的第一版需求，可改，改了要记原因 |
| 形态 | 第一期：按手机宽度做的网页；第二期：同一套界面套成 Android |
| 核心原则 | 解读只来自本地资料库，不联网、不用 AI 现搜现编 |

---

## 1. 一句话

打开随机一句毛诗，或搜到自己想起的那句；点进去看到全诗，以及这首诗被写下时的处境。处境与解读由诗词年谱、人物年谱、传记在本地拼出来，产品不替用户总结人生道理。

## 2. 要解决的问题

用户会忽然想起一句毛诗，但想不起全诗，也不知道当时为什么写。想看懂，需要三件事同时成立：

1. 诗本身长什么样  
2. 写作时的背景与情境  
3. 基于材料的解读：这首诗是怎么写成的  

没有第 2 点，诗只是句子。没有第 3 点，背景只是年表。第 3 点必须从资料里长出来，不能外挂「启示我们：职场应该……」。

精神上有没有帮助、会不会对照当下，是读完之后自己发生的，**不是产品功能，也不做单独栏目。**

## 3. 对谁、不跟谁抢

| 对象 | 关系 |
|---|---|
| 自己 | 第一用户。先做自己会反复打开的那批诗 |
| 西窗烛 | 不抢。他们做全诗词检索，我们只做毛泽东的诗 |
| 问问毛选 | 姐妹，不换皮。他们做毛选文章金句 + 现代应用；我们做毛诗 + 历史现场 |

不做：登录、社区、群聊精华、消息、个性化推荐。

## 4. 成功标准（第一期）

- 打开就能读到一句，不必先翻目录  
- 换一句、搜索、进入详情，三条路都通  
- 详情页稳定出现：全诗 / 背景与情境 / 解读  
- 每一段背景和解读都能指回本地年谱或传记，而不是网上现编  
- 手机竖屏一屏能用；电脑打开时居中成手机宽度，不做成宽门户  
- 可以放到个人网站上，面试官能点开看完一条完整路径  

## 5. 用户路径

```text
打开应用
    → 随机显示一句（不是全诗）
        → 换一句：再随机一句
        → 搜索：按诗句或诗题找回
        → 点这句：进入详情
            → 全诗
            → 背景与情境（何时、何地、当时在做什么）
            → 解读（这首诗如何写成，材料来自年谱/传记）
```

详情不展开为更多模块。第一期没有「相关推荐」「评论」「收藏账号」。卡片保存若做，也只保存上述三块，不保存鸡汤结论。

## 6. 功能需求

### P0 必须有，没有就不叫这个产品

| 编号 | 需求 | 说明 |
|---|---|---|
| F1 | 打开随机一句 | 每次打开从本地诗库抽一句残句，默认不展示全诗 |
| F2 | 换一句 | 首页明确按钮，再抽一句；避免连续抽到同一句 |
| F3 | 搜索 | 入口与「换一句」并列。支持诗句片段、诗题。无结果时允许换词再搜 |
| F4 | 详情：全诗 | 标题、词牌/诗体（若有）、全文 |
| F5 | 详情：背景与情境 | 写作时间、地点；当时在做什么。只写材料里有的事实 |
| F6 | 详情：解读 | 这首诗怎么写成。只根据已引用的年谱/传记组织，不新增外部典故充数 |
| F7 | 本地资料库 | 诗词库、年谱库、传记库。运行时不访问互联网检索 |

## 7. 内容与数据需求

产品不是先做界面再找几句诗填进去。界面是壳，资料库才是产品。

### 7.1 三张本地库

| 库 | 最少字段 | 用途 |
|---|---|---|
| 诗词库 | 诗题、全文、可检索的句子、写作时间、写作地点、关联年谱条目 | 随机、搜索、展示全诗 |
| 年谱库 | 日期或年月、地点、事件摘要、原文摘录、来源书名页码 | 还原「这一年/这段日子在做什么」 |
| 传记库 | 时期、叙述段落、来源 | 年谱过短时补处境，不替代年谱 |

### 7.2 一条详情是怎么拼出来的（第一期路径）

用户选定一首诗之后，按固定顺序查本地库，不联网：

1. 在诗词库命中该诗，读出写作时间、地点  
2. 用该时间去年谱库取同一时期事件  
3. 若年谱过短，再取传记库同一时期  
4. 合成「背景与情境」：只陈述当时处境  
5. 合成「解读」：处境如何进入这首诗、诗是怎么写成的  
6. 凡材料不足的字段，显示「资料未覆盖」，禁止用模型补全  

查找路径若与后到的纸质资料结构不合，以资料目录为准再改本段。改了记一版。

### 7.3 写入规则

- 背景：事实。不升华，不写「启示我们」  
- 解读：说明写法与处境的关系，仍须能指回材料  
- 禁止：职场建议、心灵鸡汤、无出处的心理分析  
- 第一期收录范围：先做可被年谱对上时间的诗，不追求全集  

### 7.4 依赖（未提供则解读不能上线）

需要放入项目目录的原文，格式不限（epub / PDF / txt / markdown）：

1. 毛泽东诗词集（最好带写作时间）  
2. 年谱（按年、月或日）  
3. 传记（指定可信的一版）  

未到齐之前，页面可以用一首样例诗把结构搭起来；样例的背景与解读必须空着或标明「待资料」，不得上网生成假内容。

## 8. 界面原则

- 按约 390 像素手机宽度设计，不是先做宽网页再压缩  
- 电脑访问：居中手机框，两侧留白  
- 首页：一句诗为主，动作只有「换一句」「搜索」  
- 点诗句进详情，不在首页堆简介  
- 不登录。不出现信息流、点赞、评论  

## 9. 非功能

| 项 | 要求 |
|---|---|
| 离线 | 第一期数据打进包内或本地静态文件，打开即可读 |
| 性能 | 搜索在本地完成，输入后即时出结果 |
| 版权 | 个人作品与学习用途；公开上线前再核对诗词与年谱的使用范围 |
| 可讲性 | 任何面试都能用 90 秒走完：随机 → 搜索 → 详情三块 |

## 10. 范围裁剪

| 做 | 不做 |
|---|---|
| 毛诗 | 毛选文章、全唐诗、其他诗人 |
| 随机一句 + 搜索 + 详情 | 社区、登录、消息 |
| 年谱/传记合成的背景与解读 | AI 联网问答、聊天机器人 |
| 手机宽度网页，随后套 Android | 第一期双端原生各做一遍 |

## 12. 真实制作顺序（本项目采用）

不是「先写完整 PRD 再开发」，也不是「先做完再补文档」。一人做内容型产品，按下面走。

| 步 | 做什么 | 为什么是这一步 | 本项目状态 |
|---|---|---|---|
| 1 | 把想法收成短需求 | 先分清：主路径、必须有、明确不做、内容从哪来 | 本文档 v0.1，即此步 |
| 2 | 画流程 + 出可点的手机页面 | 你要看见首页和详情，而不是想象宽度 | 下一步 |
| 3 | 并行：提供诗词集、年谱、传记 | 没有原文，解读不能做真的 | 等你放文件 |
| 4 | 用一首诗打通：搜索命中 → 查年谱 → 写出三块内容 | 先验证查找路径，再批量 | 资料到了立刻做 |
| 5 | 补随机、换一句、搜索、更多诗 | 壳已经对了，只加数据和打磨 |  |
| 6 | 放到个人网站，写一页案例 | 转产品用的是「问题-决策-结果」，不是安装包本身 |  |
| 7 | 同一套界面套 Android | 交互不再重做 | P2 |

因此：

- **现在不先写长 PRD，也不先埋头做完再写文档。** 先有这一份短需求。  
- **下一步不是等全部文件齐了才动手，也不是直接做完整产品。** 下一步做两页可点 demo（首页、详情），宽度按手机。  
- **文件仍然要给。** 没有文件，详情里的背景和解读只能空着。你给文件和我做页面可以同时进行。  
- **原型：不单独先画一套完整设计稿。** 对这个产品，可点的手机页面就是原型。结构不对再改页面，比先画 20 张静态图快。
