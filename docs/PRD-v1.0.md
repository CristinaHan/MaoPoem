## 1. 一句话

打开随机一句毛诗（完整句，不是半句），或搜到自己想起的那句；点进去看到全诗、这首诗被写下时的处境，以及基于材料的解读。

## 2. 要解决的问题

用户会忽然想起一句毛诗，但想不起全诗，也不知道当时为什么写。看懂一句诗需要三件事同时成立：

1. **诗本身长什么样** —— 全诗、完整句子、诗体与创作时间
2. **写作时的背景与情境** —— 何时、何地、当时在做什么
3. **基于材料的解读** —— 这首诗是怎么写成的

没有第 2 点，诗只是句子；没有第 3 点，背景只是年表。第 3 点必须从资料里长出来，不能外挂"启示我们：职场应该……"。

**精神上有没有帮助、会不会对照当下，是读完之后自己发生的，不是产品功能，也不做单独栏目。**

## 3. 用户与场景

| 用户 | 场景 | 需求 |
|---|---|---|
| 自己（第一用户） | 忽然想起一句毛诗，想不起全诗/出处/写作背景 | 随机遇见、定向找回、一看就懂 |
| 面试官/访客 | 90 秒了解产品 | 三条路走通：随机 → 搜索 → 详情 |
| 毛诗爱好者（潜在） | 日常翻阅、收藏分享 | 安静阅读、收藏管理、存图分享 |

不服务：需要 AI 问答、社区互动、全诗词库检索的用户（那是别人的产品）。

## 4. 目标与不抢

| 对象 | 关系 |
|---|---|
| 西窗烛 | 不抢。他们做全诗词检索；我们只做毛泽东的诗 |
| 问问毛选 | 姐妹，不换皮。他们做毛选文章金句 + 现代应用；我们做毛诗 + 历史现场 |
| 古诗文网 | 不抢。他们做古诗文全库 + 注释；我们做「这句诗当时为什么写」 |

**不做**：登录、社区、评论、个性化推荐、AI 问答、广告、统计 SDK。

## 8. 数据模型（成品库字段级）

`content/poems/<id>.json` —— 63 个文件，每首一首：

```json
{
  "order": 47,              // 排序（文集顺序）
  "id": "xianrendong",      // 唯一标识（罗马音）
  "title": "七绝·为李进同志题所摄庐山仙人洞照",
  "form": "七绝",           // 诗体：七绝/七律/词/杂言…
  "date": "1961年9月",       // 创作时间（阿拉伯数字存，展示转中文）
  "place": "江西庐山",       // 创作地点（可空）
  "originalTitle": "",      // 原题（与通行题不同时填写）
  "excerpt": "天生一个仙人洞，无限风光在险峰",  // 代表句（可空，兜底 lines[0]）
  "lines": [                // 每行 = 一个完整句（句号/问号/叹号结尾）
    "暮色苍茫看劲松，乱云飞渡仍从容。",
    "天生一个仙人洞，无限风光在险峰。"
  ],
  "searchText": "…",        // 检索冗余（题/句/地点/时间拼接）
  "complete": true,         // 内容是否写就
  "background": [ "…" ],    // 写作背景段落（事实，可溯源）
  "interpretation": [ "…" ],// 诗词解读段落（写法与处境）
  "sources": [ "《毛泽东年谱…》", "《毛泽东诗词全编鉴赏》…" ]  // 材料出处
}
```

**收藏记录**（localStorage `maoshi-saved`）：

```json
{ "id": "changsha", "lineIndex": -1, "kind": "poem", "time": 1725000000000 }
```

- `kind: "poem"` 整首收藏（lineIndex 恒为 -1）；`kind: "line"` 单句收藏（lineIndex 指向 lines 下标）
- 老数据迁移：纯 id 字符串数组自动迁移为结构化记录

**用户偏好**（localStorage）：字体 / 字号（pt，旧档位 xs–xl 自动迁移）/ 皮肤（旧「丹笺」皮肤迁移到「暖棕」）/ 背景（none|custom + dataURL + 透明度）。

## 9. 内容体系与生产管线

### 9.1 两层库

```
第 1 层 素材库（编辑用，不进 App）        第 2 层 成品库（App 的数据）
年谱全九卷 → 年/日期/条目                  content/poems/<id>.json × 63
传记 → 章节/段落                          每首：全诗/背景/解读/出处
鉴赏 → 63 首文章（toc 已索引）
        ↓ 写稿（AI 起草 + 人工审稿）
        content/poems/*.json
        ↓ kb.py 构建
        web/data/poems.js   ← 只有这份进用户包/APK
```

### 9.2 写稿规则（内容可信的底线）

- 背景：**事实**。不升华，不写「启示我们」
- 解读：说明写法与处境的关系，仍须能指回材料
- 叙述是合成文字，禁止「年谱说 / 传记记载 / 鉴赏写道」等字样
- 日期用阿拉伯数字存储（首页展示转中文数字）
- 材料不足的字段写「资料未覆盖」，**禁止 AI 补全**
- 后见之明标在解读末段，不混进写作当时
- 收录范围：可被年谱对上时间的诗优先；一期 63 首全部对上

### 9.3 拆句规范

- `lines` 每行一句（律诗一联、词自然句），**句号/问号结尾，必须完整**
- 律诗 4 行、绝句 2 行、词按自然句；禁止半句入库
- 首页按行（句号单位）随机抽取——**每句都有机会上首页**（全库校验：303 行全部以句末标点结尾）

### 9.4 构建与校验

- `tools/kb.py`：content/ → `web/data/poems.js`（构建时全量校验字段完整性）
- `tools/make-brand.py`：手迹「星」「火」单字图 → `web/brand.png` + `web/brand-data.js`（dataURL 内嵌，供 canvas 存图防污染）
- `tools/make-preview.py` / `analyze-brand.py`：素材与品牌图校验辅助

## 10. 关键体验决策（面试可讲）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 随机展示完整句（句号单位） | 每个句子都有机会被看见；「回忆半句想不起全诗」是产品要解决的原问题 |
| 2 | 换一句在右侧主按钮 | 右利手拇指热区；主行动最易触达（按钮 48px 不缩） |
| 3 | 返回保持原句 | 从详情/搜索/设置返回首页不换句——用户心理模型是「回来看刚才那句」 |
| 4 | 皮肤 = 整套配色 | 不做独立字体颜色功能：职责重叠，冲突时无从裁决（微信读书同思路） |
| 5 | 详情页整句一行 + 15px 正文 | 七绝/七律整句不提前换行（16 字符 ≈ 250px，窄屏放下）；词的长短句自然错落；字号与主流阅读应用一致 |
| 6 | Android 壳 textZoom 固定 100 | WebView 默认跟随系统字体大小设置，会把字号放大成「老年版」——固定 100% 后与设计稿一致 |
| 7 | 存图为竖屏长图 | 手机阅读场景的分享载体是竖屏；皮肤/背景/手迹品牌全部入图，所见即所得 |
| 8 | 品牌图 dataURL 内嵌 | file:// 下 canvas 绘制本地图片会污染导致 toBlob 报错——dataURL 同源安全，Web/APK 双端可用 |
| 9 | 收藏导出/导入严格校验 | 导入只收「id 在库 + 整数索引 + kind 语义 + 时间合法」的记录，坏文件不破坏现有收藏 |
| 10 | 状态栏随皮肤融合 | 卡片背景色蔓延到系统状态栏（setStatusBarColor），深色皮肤自动切白字图标——细节决定质感 |
| 11 | 不做字体颜色独立设置 | 见 #4 |
| 12 | 无网络依赖 | 内容真实性靠「本地资料 + 人工审稿」而非联网检索 |
| 13 | 弹窗居中顶层 | 确认框/存图预览/成功提示一律 fixed 全屏居中（显式 top/left/right/bottom，兼容老 WebView；z-index 60 不被视图规则覆盖）——用户反馈"在底部反人类"后修复 |
| 14 | 存图字体与详情页一致 | 存图 canvas 与详情页共用 `--font-reading`——曾因存图单独硬编码草书毛体字体导致图文不一致（用户实测发现），已删除该字体并统一取字逻辑 |
| 15 | 背景仅用于诗句与详情页 | 自定义背景不铺满全局，只叠加首页诗句区域与详情页（用户明确要求）；其余页面保持纯净 |
| 16 | App 内无解释类文字 | 设置提示只给结论（如"支持 PNG / JPG / WebP / GIF / BMP"），不带括号说明、不带引导语——用户多次强调，视为铁律 |
| 17 | 二次确认（涉及存储的操作） | 存图先出预览图、导出/导入先确认——给用户反悔机会，防误触产生垃圾文件 |

**体验改进待办**（F16）：导出/导入/存图前二次确认（存图先生成预览图）——涉及存储的操作给用户一个反悔机会，防误操作。
